<task type="auto">
  <name>Task 1: Install buf and create buf.yaml + buf.gen.yaml</name>
  <files>proto/buf.yaml, buf.gen.yaml</files>
  <action>
First, verify buf is installed: run `buf --version`. If not found, install via `brew install bufbuild/buf/buf` and verify again.

Create `proto/buf.yaml` (inside the proto/ directory):
```yaml
version: v2
modules:
  - path: .
lint:
  use:
    - DEFAULT
breaking:
  use:
    - FILE
```

Note: buf.yaml is placed INSIDE proto/ so the module path is `.` (the proto/ dir itself). Do NOT add `name:` field -- only needed for BSR push which is out of scope.

Create `buf.gen.yaml` at repo root (NOT inside proto/):
```yaml
version: v2
managed:
  enabled: true
  override:
    - file_option: go_package_prefix
      value: github.com/afterdarksys/adsops-utils/gen/go
plugins:
  - remote: buf.build/protocolbuffers/go
    out: gen/go
    opt:
      - paths=source_relative

  - remote: buf.build/protocolbuffers/python
    out: gen/python
    opt:
      - paths=source_relative

  - remote: buf.build/protocolbuffers/pyi
    out: gen/python
    opt:
      - paths=source_relative
inputs:
  - directory: proto
```

Key points:
- managed mode with go_package_prefix means proto files must NOT contain `option go_package` -- buf injects it at generation time
- Three plugins: Go messages, Python _pb2.py, Python .pyi type stubs
- paths=source_relative is REQUIRED for Go to avoid nested directory issues
- No gRPC plugins -- not needed for v1
- No version pins on plugins -- use latest; pin after first successful generation if desired

Create the proto directory structure: `mkdir -p proto/adsops/v1`

<task type="auto">
  <name>Task 2: Create gen/go/go.mod and add Makefile proto targets</name>
  <files>gen/go/go.mod, Makefile</files>
  <action>
Create `gen/go/go.mod` for the generated Go bindings as a separate module:
```
module github.com/afterdarksys/adsops-utils/gen/go

go 1.21

require google.golang.org/protobuf v1.34.1
```

Create the directory: `mkdir -p gen/go`

Then run `cd gen/go && go mod tidy` to populate go.sum. The protobuf dependency must match or exceed the version in the root go.mod (v1.34.1).

Append proto targets to the existing root Makefile. Add to the `.PHONY` line at the top: `proto-gen proto-lint proto-breaking`. Then add these targets at the end of the Makefile, following the existing `## target: description` comment convention used by the help system:

```makefile

## proto-gen: Generate Go and Python bindings from .proto files
proto-gen:
	buf generate
	find gen/python -type d -exec touch {}/__init__.py \;

## proto-lint: Lint .proto files
proto-lint:
	buf lint proto/

## proto-breaking: Check for breaking changes against main
proto-breaking:
	buf breaking proto/ --against '.git#branch=main'
```

IMPORTANT: The proto-gen target MUST include the `find gen/python -type d -exec touch {}/__init__.py \;` post-step because protoc does NOT generate __init__.py files. Without this, Python imports will fail with ModuleNotFoundError.

Update the .PHONY line to include the new targets. The existing .PHONY line is:
`.PHONY: all build clean test lint run-api run-cli migrate help`
Add `proto-gen proto-lint proto-breaking` to it.

  </verify>
